# Материалы для самостоятельного изучения (Воркшоп №3)

**Тема воркшопа:** Контейнеризация и оркестрация: Docker, Docker Compose, менеджер зависимостей
**Время на подготовку:** около 1 часа 25 минут — 75 минут чтения и 10 минут практической проверки

На воркшопе вы будете проектировать схему окружения своего проекта (FastAPI + PostgreSQL в Docker Compose) и выбирать менеджер зависимостей. Лекции не будет: всё, что нужно для работы на занятии, — в списке ниже. Список сокращён до обязательного минимума, дополнительных материалов нет.

## 2. Практическая проверка (10 мин)

Выполните на своей машине. Команды одинаково работают в PowerShell, Git Bash, macOS и Linux.

**Шаг 1.** Запустить PostgreSQL 16 в контейнере, ничего не устанавливая локально:

```bash
docker run -d --name w3-db -e POSTGRES_PASSWORD=w3 postgres:16
```

Первый запуск скачает образ (около 170 МБ, на медленном канале — несколько минут). Это заодно избавит вас от скачивания на практике №3.

**Шаг 2.** Через несколько секунд выполнить запрос внутри контейнера:

```bash
docker exec w3-db psql -U postgres -c "select version();"
```

**Ожидаемый вывод:** таблица из одной строки, содержащей `PostgreSQL 16.`. Если видите `connection to server on socket ... failed: No such file or directory` или `the database system is starting up` — база ещё инициализируется, повторите через несколько секунд. Этот эффект — ровно тот случай, ради которого читается материал 3.

**Шаг 3.** Удалить контейнер вместе с его безымянным томом:

```bash
docker rm -f -v w3-db
```

**Перед тем как выполнить шаг 3, ответьте себе на вопрос:** если бы вы создали в этой базе таблицу, осталась бы она после `docker rm` и повторного `docker run`? Проверять не нужно — на воркшопе проверим вместе.

## 3. Вопросы для самопроверки

На воркшопе эти вопросы не будут разбираться отдельно — на них опирается работа в командах. Если на какой-то вопрос нет ответа, вернитесь к материалу из таблицы.

1. Чем образ отличается от контейнера? Что из них вы публикуете в реестр?
2. Приложение и база запущены в одном `compose.yaml`. По какому адресу приложение подключается к базе: `localhost`, IP-адрес или что-то третье? Почему?
3. Что произойдёт с данными PostgreSQL после удаления контейнера, если том не подключён?
4. Почему `depends_on: [db]` недостаточно, чтобы приложение не упало при старте?
5. Какой файл нужно коммитить, чтобы у всех участников команды и в Docker-образе стояли одинаковые версии пакетов? Чем он отличается от `requirements.txt`, полученного через `pip freeze`?
6. Зачем фиксировать версию образа (`postgres:16`), а не использовать `postgres:latest`?

## 4. Что читать сейчас НЕ нужно

Чтобы уложиться в отведённое время, отложите:

- написание `Dockerfile`, multi-stage build, non-root пользователь — это практика №3 и №4;
- переменные окружения, `.env`, `pydantic-settings`, секреты — это воркшоп №4;
- Kubernetes, Docker Swarm и прочие оркестраторы кластерного уровня — в курсе не используются.

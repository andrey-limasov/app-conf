## Назначение документа

Этот документ отслеживает **прогресс разработки методического комплекта** курса "Управление конфигурацией бизнес-приложений". Документ служит для:

1. **Понимания текущего состояния** — какие материалы готовы, какие в работе, какие запланированы
2. **Определения следующей задачи** — что разрабатывать дальше с учётом приоритетов и зависимостей
3. **Проверки полноты** — все ли необходимые материалы созданы к началу соответствующей недели
4. **Планирования** — какие материалы нужны заблаговременно (за 1-2 недели до использования)

**Ключевой принцип:** Материалы для занятия недели N должны быть готовы **до конца недели N-2** и **закоммичены в соответствующую ветку**. Файл, лежащий на диске, но не попавший в git, считается несуществующим.

**О датах:** версия 1.0 этого документа планировала февраль–май 2025 и полностью устарела. Планирование переведено на относительные недели. Абсолютные дедлайны появятся, когда в метаданных будет зафиксирован `semester_start`.

## Легенда статусов

| Статус | Значение |
|---|---|
| ✅ `DONE` | Завершено, закоммичено в нужную ветку |
| 🔄 `IN_PROGRESS` | В активной разработке |
| 📋 `TODO` | Запланировано, не начато |
| ⏸️ `BLOCKED` | Заблокировано внешней зависимостью |
| ❌ `DEFERRED` | Отложено |

**Приоритеты:**
- **P0 (Critical)** — блокирует проведение занятия или сохранность материалов
- **P1 (High)** — нужно к началу соответствующего модуля
- **P2 (Medium)** — желательно иметь, но не блокирует
- **P3 (Low)** — опционально

## Порядок работы с документом

### Как использовать этот документ

**Сценарий 1: "Что делать дальше?"**
1. Найти этап со статусом 🔄 IN_PROGRESS
2. Взять задачу 📋 TODO с наивысшим приоритетом (P0 > P1 > P2)
3. Проверить зависимости
4. Определить ветку из колонки «Ветка» и работать в соответствующей рабочей папке

**Сценарий 2: "Готовы ли мы к неделе N?"**
1. Найти этап, соответствующий неделе N
2. Проверить статусы всех задач этапа
3. Проверить, что файлы действительно в git (`git ls-files`), а не только на диске

**Сценарий 3: "Какие материалы нужны для воркшопа N?"**
1. Найти строки `workshop-N-*` в таблицах этапов
2. Проверить обе ветки: студенческие материалы в `main`, сценарий и листы оценки в `teacher`

**Сценарий 4: "Обновить прогресс"**
1. После коммита документа изменить статус на ✅ DONE с датой
2. Обновить счётчики в разделе «Общее состояние проекта» и «Метрики»
3. Обновить статус этапа, если все задачи завершены
4. Дописать строку в «Историю изменений» при существенных правках

### Правила обновления ROADMAP

1. **Статус ✅ DONE ставится только после коммита**, не после создания файла на диске
2. Указывать дату завершения
3. Не удалять задачи — только менять статус на ❌ DEFERRED с причиной
4. Проверять зависимости перед началом задачи
5. Не менять приоритеты без обоснования в «Истории изменений»
6. В сообщениях коммитов не использовать строки соавторства и ссылки на внешние сервисы — коммит подписывается только автором курса
